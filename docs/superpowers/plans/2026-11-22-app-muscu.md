# App de suivi musculation — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** une PWA iPhone, locale et gratuite, pour saisir ses séances PPL avec des séries pré-remplies par la double progression, et voir sa progression via un bilan hebdomadaire.

**Architecture :** une SPA React servie en statique. Toute la logique métier (progression, indicateurs) vit dans `src/domain/` en fonctions pures testées. Les données passent par une seule couche `src/data/` (Dexie/IndexedDB), pour qu'un serveur puisse la remplacer plus tard. L'UI dans `src/features/` ne parle qu'à `src/data/` et `src/domain/`.

**Tech Stack :** Vite, React 18, TypeScript (strict), vite-plugin-pwa, Dexie (+ dexie-react-hooks), React Router, Framer Motion, Recharts, Vitest, @testing-library/react, fake-indexeddb, déploiement GitHub Pages via GitHub Actions.

**Spec :** `docs/superpowers/specs/2026-11-22-app-muscu-design.md`

## Global Constraints

- iPhone : Safari et Chrome. Installable sur l'écran d'accueil. Fonctionne hors ligne.
- Coût nul. Aucun serveur, aucun compte. Données uniquement sur l'appareil.
- Interface en français uniquement. Unités en kg. Les poids s'affichent avec une virgule (`77,5 kg`).
- Semaine = du lundi au dimanche, en heure locale.
- Incréments : haltères 2 kg, fentes avec sac 2 kg, machines/poulies/barre 2,5 kg. Modifiables par exercice.
- Baisse de charge : −10 %, arrondie à l'incrément inférieur, après 3 échecs consécutifs.
- Pas de minuteur, pas de notifications, pas de vibration.
- Animations < 300 ms, interruptibles, sans jamais bloquer la saisie. Mode sombre. Grandes zones tactiles.
- Inspiration Revolut pour le ressenti uniquement : ni sa marque, ni ses couleurs, ni ses éléments graphiques.
- Tests Vitest obligatoires sur tout `src/domain/`.

## Décisions prises en écrivant le plan (à faire valider par Tim)

- **Séance non terminée :** le spec prévoit une clôture automatique à l'ouverture suivante. Or iOS ferme souvent les PWA en arrière-plan, donc rouvrir l'appli en pleine séance clôturerait celle-ci. Règle retenue : à l'ouverture, une séance non terminée **reprend** si elle a commencé il y a moins de 6 h. Au-delà, elle est clôturée automatiquement.
- **Correspondance des muscles de free-exercise-db vers les 10 groupes :**
  - abdominals → abdos ; abductors, glutes → fessiers ; adductors, quadriceps → quadriceps ;
  - biceps, forearms → biceps ; calves → mollets ; chest → pectoraux ; hamstrings → ischios ;
  - lats, lower back, middle back, traps, neck → dos ; shoulders → épaules ; triceps → triceps.
  - Exceptions dans le template de Tim : le soulevé de terre est forcé sur ischios.

## Review Focus

1. **Poids décimal tapé avec une virgule** (« 77,5 » au clavier français) : il doit être accepté et enregistré comme 77.5. → test dans Task 7.
2. **Semaine à cheval sur un changement d'heure ou une séance juste après minuit le dimanche** : la séance compte pour la semaine de sa date locale de début. → test dans Task 5.
3. **Template modifié après coup** (fourchette changée, exercice retiré) : l'historique reste intact. La proposition utilise la nouvelle fourchette. L'exercice retiré reste visible dans le bilan des semaines passées. → tests dans Tasks 4 et 5.
4. **Import d'un fichier invalide, ou d'une version de format inconnue** : il est refusé avec un message clair, et les données existantes restent intactes. → test dans Task 2.
5. **Appli tuée par iOS en pleine séance** : à la réouverture, la séance reprend avec les séries déjà validées. → test dans Task 7.

### Task 4 : Moteur de double progression

**Files :**
- Create : `src/domain/progression.ts`
- Test : `src/domain/progression.test.ts`

**Interfaces :**
- Produces :
```ts
export interface PerformedSet { weight: number; reps: number }
export interface ExerciseResult { date: string; sets: PerformedSet[] } // séries validées seulement, dans l'ordre ; une séance sans série validée n'apparaît pas
export interface Slot { sets: number; repsMin: number; repsMax: number }
export type Suggestion =
  | { kind: 'none' }                                  // aucun historique
  | { kind: 'add-load' }                              // poids du corps, fourchette atteinte sans lest
  | { kind: 'sets'; reason: 'increase'|'repeat'|'deload'; sets: PerformedSet[] };
export function referenceWeight(r: ExerciseResult): number;   // poids de la 1re série
export function isFailure(r: ExerciseResult, slot: Slot): boolean;
export function suggestNext(history: ExerciseResult[], slot: Slot, ex: Pick<Exercise,'increment'|'bodyweight'>): Suggestion; // history du plus ancien au plus récent
```

Règles (spec §7) :
- `isFailure` est vrai si l'une des `slot.sets` premières séries validées a `reps < repsMin`.
- Hausse de charge si la dernière séance a au moins `slot.sets` séries validées, que les `slot.sets` premières sont toutes au poids de référence et toutes à `reps ≥ repsMax`. Le résultat est alors `slot.sets` séries à `ref + increment`, `repsMin` répétitions. Exception : poids du corps avec `ref === 0`, qui renvoie `add-load`.
- Baisse de charge si le compteur d'échecs consécutifs atteint 3 ou plus et que `ref > 0`. Le résultat est `slot.sets` séries à `floor(ref × 0,9 / increment) × increment`, `repsMin` répétitions. Compteur : on remonte l'historique depuis la séance la plus récente et on s'arrête à la première séance qui n'est pas un échec, ou dont le poids de référence diffère de celui de la plus récente (une hausse ou une baisse de charge remet donc le compteur à zéro).
- Sinon, on reconduit (`repeat`) : même poids de référence, et pour chaque série i < `slot.sets`, les répétitions de la série i de la dernière séance si elle existe, sinon `repsMin`.

- [ ] **Step 1 : écrire les tests qui échouent** (incrément 2,5 sauf mention contraire, slot 3 × 8–12) :
  - `none` : historique vide → `{kind:'none'}` ;
  - `increase` : dernière séance 80×12, 80×12, 80×12 → 3 × 82,5×8 ;
  - `repeat` : 80×12, 80×11, 80×10 → 80×12, 80×11, 80×10 ;
  - `repeat` avec série manquante : 80×12, 80×12 → 80×12, 80×12, 80×8 ;
  - le réel prime sur le prévu : dernière séance 85×12 ×3 alors que 80 était prévu → 3 × 87,5×8 ;
  - séries en plus ignorées : 80×12 ×3 puis 60×6 → `increase` ;
  - `deload` : 3 séances à 80 qui sont chacune un échec (80×7, 80×8, 80×8) → 3 × 70×8 ;
  - pas de baisse après 2 échecs ;
  - reset : échec, échec, réussite, échec → `repeat` ;
  - reset par changement de poids : échecs à 77,5 ×2 puis échec à 80 → `repeat` ;
  - après une baisse : séance suivante à 70 en échec → `repeat` (le compteur repart à 1) ;
  - haltères (incrément 2) : 24×12 ×3 → 3 × 26×8 ;
  - poids du corps : 0×12 ×3 → `add-load` ; 0×7 ×3 séances → `repeat` (pas de baisse à 0 kg) ; lest 5×12 ×3 → 3 × 7,5×8 ;
  - changement de fourchette (Review Focus 3) : dernière séance 80×10 ×3, slot passé à 3 × 6–10 → `increase`.

### Task 5 : Indicateurs et bilan hebdomadaire

**Files :**
- Create : `src/domain/dates.ts`, `src/domain/metrics.ts`
- Test : `src/domain/dates.test.ts`, `src/domain/metrics.test.ts`

**Interfaces :**
- Consumes : `AppData`, `Exercise`, `MuscleGroup` (Task 2).
- Produces :
```ts
export function weekStart(iso: string): string;            // 'YYYY-MM-DD' du lundi, heure locale
export function e1rm(weight: number, reps: number): number; // weight * (1 + reps/30)
export function isBetter(a: PerformedSet, b: PerformedSet, bodyweight: boolean): boolean; // e1RM ; si poids du corps : comparaison (poids, puis reps)
export type Delta = { kind: 'weight'; value: number } | { kind: 'reps'; value: number } | { kind: 'same' } | { kind: 'new' };
export interface ExerciseWeek { exerciseId: string; group: MuscleGroup; sets: number; best: PerformedSet; delta: Delta; isRecord: boolean; stagnantWeeks: number }
export interface WeeklySummary { weekStart: string; sessionsDone: number; sessionsPlanned: 3; recordsCount: number; setsByGroup: Record<MuscleGroup, number>; exercises: ExerciseWeek[] }
export function weeklySummary(data: AppData, weekStartIso: string): WeeklySummary;
export function exerciseSeries(data: AppData, exerciseId: string, weeks: number, endWeek: string): { weekStart: string; value: number | null }[]; // e1RM, ou reps de la meilleure série au poids du corps sans lest
```

Règles :
- Seules les séries `done` comptent. Une séance compte dans `sessionsDone` si elle a au moins une série validée.
- `setsByGroup` compte les séries validées et les attribue uniquement au `primaryGroup` de l'exercice.
- `delta` compare la meilleure série de la semaine à la meilleure série de la dernière semaine précédente où l'exercice a été fait :
  - `weight` si le poids a augmenté ;
  - `reps` si le poids est égal et les répétitions supérieures ;
  - `same` dans tous les autres cas ;
  - `new` s'il n'y a aucune semaine antérieure.
- `isRecord` est vrai si la meilleure série de la semaine bat (`isBetter`) toutes les séries antérieures de cet exercice.
- `stagnantWeeks` est le nombre de semaines consécutives où l'exercice a été fait sans progrès (`same`), en remontant depuis la semaine affichée. L'UI passe en orange à partir de 3.
